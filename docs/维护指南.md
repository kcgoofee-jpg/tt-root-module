# TT 守护 · 维护指南

给以后修小问题的人（包括 Claude Sonnet）看。先读完「必须遵守」和「踩过的坑」再动手。

## 必须遵守（用户的规定）

- **模块只能由用户在 KernelSU 管理器里安装**。不要用 adb 安装、更新模块，也不要把文件直接复制进 `/data/adb/modules/claudemax_tt_keepalive/` 来「热更新」。做法：构建 zip → `adb push` 到手机 `/sdcard/Download/` → 请用户安装并重启。
- **不 force-stop、不重启正在用的 TT**。动 TT 之前，先查 Mac 代理 `curl -s http://127.0.0.1:8901/v1/control/status` 里的 `busy`，`busy=0` 才算空闲。
- **不重启手机**。不改系统或安全设置，除非是模块自己负责、卸载时会还原的值；临时改过的（比如 `svc power stayon`）用完立刻改回，并告诉用户。
- **不截聊天界面**，不看用户生成的图片；只看日志。需要截图时，先确认屏幕上是模块界面或测试用的应用。
- **不永久删除用户数据**。要删的东西移到 `tavern/backups/<日期>/`。
- **发布到 GitHub**（新 release、公开仓库的改动）要用户同意；这个仓库已公开，用户已同意发布版本。
- **git 提交结尾加** `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`（按当前模型改名）。
- **回复用户用中文**。界面文案：标准化、像系统设置，不用口语、不写 AI 腔的解释。

## 仓库结构

| 路径 | 作用 |
|---|---|
| `ksu-tt-keepalive/common.sh` | 公共函数：配置、状态、目标（酒馆）、备份、实时副本、防冻结、温度、事件记录 |

| `ksu-tt-keepalive/ui.sh` | 界面和电脑端调用的命令（`status` 输出 JSON，`set`、`backup`、`restore`、`list-backups`…） |

| `ksu-tt-keepalive/webroot/index.html` | 界面（单文件；没有 KernelSU 时显示演示数据） |
| `ksu-tt-keepalive/retention.awk` | 分层保留规则（手机和电脑共用） |
| `pc/` | 电脑端同步：`pull-backups.sh`（Mac）、`pull-backups.ps1`（Windows）及安装脚本 |
| `tests/cases.sh` | 模块测试（dash / sh / ksh 各跑一遍），假命令模拟 Android |
| `tests/pc-cases.zsh` | 电脑端测试（假 adb，手机那头跑真的 ui.sh） |
| `tests/win-cases.ps1` | Windows 测试（只在 GitHub Actions 的 Windows 上跑） |
| `tests/run-on-phone.sh` | 在手机的 mksh 和 busybox 上跑 `cases.sh` |
| `tests/ui-harness.sh` | 用手机真实数据在电脑浏览器里测界面 |

## 修改流程

1. 改代码。新功能或修 bug 都要在 `tests/cases.sh`（或 `pc-cases.zsh`）加用例，先让它失败，再修到通过。
2. 本机测试：`sh tests/run.sh`，**必须全过**。
3. 需要时在手机上跑：`ADB=… ANDROID_SERIAL=… zsh tests/run-on-phone.sh`（手机的 toybox / busybox 和 Mac 不一样，见下）。
4. 界面改动：浏览器打开 `webroot/index.html` 看演示数据（场景下拉框可切换）；要看真实数据用 `zsh tests/ui-harness.sh`。检查手机宽度（375px）下没有横向溢出。
5. 发布：`module.prop` 的 `version` 和 `versionCode` 加一 → `update.json` 同步 → `CHANGELOG.md` 写一条 → `zsh build-ksu-module.sh`（会先跑测试）→ push 到手机 `/sdcard/Download/` → 提交、推送 → `gh release create v版本 dist/…zip`。
6. 推送后 GitHub Actions 会在 macOS 和 Windows 上跑测试，确认通过。

## 在手机上排查

- 日志：`adb shell su -c 'tail -50 /data/adb/tt-guard/service.log'`
- 状态：`adb shell su -c 'sh /data/adb/modules/claudemax_tt_keepalive/ui.sh status'`（JSON）；自检：`… ui.sh selftest`
- 要在手机上试改过的脚本：推到 `/data/local/tmp/ttg-mod/`，用 `TT_MODDIR=/data/local/tmp/ttg-mod TT_GUARD_DIR=/data/local/tmp/ttg-g` 运行，**用完删掉**，不要碰正式安装的模块目录。
- 以 Termux 或其他应用的身份跑命令：`su -g <uid> -G 3003 -G 9997 <uid> -c …`（不加 `-G 3003` 就没有网络）。

## 踩过的坑（改代码前看一遍）

- **变量后面紧跟中文**：`"TT（$pid）"` 在 UTF-8 环境的 bash 里会把 `）` 的字节当成变量名的一部分。一律写 `${pid}`。
- **排序和去重中文**：macOS 在 UTF-8 下 `uniq` 会把不同的中文当成相同。用 `LC_ALL=C sort | LC_ALL=C uniq -c`。
- **手机的 `tr`**：toybox 的 `tr -d '\000-\037'` 会把 `-` 也删掉。用 `tr -d '[:cntrl:]'`。
- **变量互相覆盖**：shell 函数默认共享全局变量。`space_ok` 会改 `last`、很多函数用 `n`、`f`、`t`。新函数里的循环变量用不容易撞的名字（`lv_last`、`af_n`、`cb_`），或写成子 shell 函数 `f() ( … )`。
- **给函数加前缀赋值**：`FOO=1 some_function` 在 POSIX sh 里不可靠（有的 shell 会保留、有的不传给子进程）。测试里用 `export FOO=1; some_function`。
- **adb shell 会吃掉标准输入**：在 `while read` 循环里调 `adb shell` 要加 `</dev/null`。
- **zsh 的 `path` 是 `PATH`**：不要用 `path` 当变量名。zsh 里 `${VAR:+-s $VAR}` 不会拆成两个参数，用数组。
- **这台 Mac 的交互 shell 里 `cat` 是 bat 的别名、`ls` 是 eza**：脚本和命令里用 `/bin/cat`、`/bin/ls`。
- **静态检查**：`tests/cases.sh` 检查模块没有往 `/proc` 写东西、写 cgroup 只有防冻结一处（`> "$cg"`）。别的地方需要写这类文件要先想清楚。
- **界面**：KernelSU 的 `ksu.exec(命令, "{}", 回调函数名)`；`ui.sh status` 要调很多系统命令，别每秒轮询。界面先用本机缓存的上次状态画出来，再在后台刷新。
- **ColorOS 冻结**：hans 在应用级 cgroup（`/sys/fs/cgroup/apps/uid_<uid>/cgroup.freeze`）冻结，`am unfreeze --sticky` 无效。

## 交给 Sonnet 的任务范围

适合：文案调整、界面小问题、单个函数的 bug（能写出测试复现的）、文档更新、测试补充。
不适合（交回给用户或更强的模型）：改动保活 / 冻结策略、恢复逻辑、电脑端同步协议、任何会改系统设置的东西、发布前的整体检查。

每次改完在回复里写明：改了什么、测试结果（`sh tests/run.sh` 的「通过 N，失败 0」）、是否需要用户重新安装模块。
